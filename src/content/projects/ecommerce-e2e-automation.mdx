## Context

The e-commerce platform served 500K+ monthly users and had grown organically over 5 years, accumulating significant technical debt. Manual regression testing took 4+ hours per release, creating a bottleneck that limited the team to fortnightly deployments. Critical checkout and payment flows were particularly fragile, with production incidents occurring roughly once per month.

## Testing Strategy & Rationale

I chose **Playwright over Cypress** for several key reasons:

1. **Multi-browser support** — The platform had a significant Safari user base (28%), and Playwright's WebKit engine testing was essential. Cypress didn't support Safari at the time.
2. **API testing integration** — Playwright's `request` context allowed us to seed test data via API calls within the same test, eliminating the need for a separate API testing tool for E2E scenarios.
3. **Parallel execution** — Playwright's built-in parallelism with worker isolation meant we could run 150+ tests in under 5 minutes across 6 workers.
4. **Auto-waiting** — Reduced flakiness compared to explicit waits, which was critical for the team's confidence in the automation suite.

**Trade-offs considered:**

- Cypress had better debugging with time-travel, but the team prioritised speed and browser coverage.
- Selenium was rejected due to the maintenance overhead of WebDriver setup and slower execution.

## Scope

The testing scope covered:

- **E2E User Journeys** — Product search → add to cart → checkout → payment → order confirmation
- **API Contract Testing** — 23 REST endpoints validated for response schemas, error handling, and business logic
- **Cross-Browser** — Chrome, Firefox, and WebKit (Safari)
- **Responsive** — Mobile (375px), Tablet (768px), Desktop (1280px)
- **Accessibility** — axe-core integration scanning all critical user flows for WCAG 2.2 AA compliance

## Challenges & How I Solved Them

### Challenge 1: Flaky Payment Gateway Tests

The third-party payment sandbox had intermittent 3-5 second delays, causing timeout failures in 15% of test runs.

**Solution:** Implemented a retry strategy with exponential backoff specifically for payment-related assertions, combined with a mock payment gateway for non-payment-specific tests. This reduced flakiness from 15% to under 1%.

### Challenge 2: Test Data Management

Each test needed a unique user account, product inventory, and order state. Shared test data caused cascading failures.

**Solution:** Created a `TestDataFactory` utility that used API calls to provision isolated test data before each test suite, with automatic cleanup via `afterAll` hooks. Each test ran in complete isolation.

### Challenge 3: CI Pipeline Speed

The initial CI run took 25 minutes, which was unacceptable for the team's PR workflow.

**Solution:** Implemented sharding across 4 CI runners using Playwright's built-in `--shard` flag, bringing total CI time down to 7 minutes. Also added selective test execution based on changed files using a custom GitHub Action.

## Key Takeaways

1. **Start with the highest-risk flows** — Automating checkout and payment first delivered 60% of the value in the first 3 weeks.
2. **Invest in test data isolation early** — It's tempting to share data for speed, but the maintenance cost of flaky tests far exceeds the setup cost of isolated data.
3. **Make the CI pipeline fast or nobody will use it** — The 25→7 minute reduction was the single biggest factor in developer adoption.
